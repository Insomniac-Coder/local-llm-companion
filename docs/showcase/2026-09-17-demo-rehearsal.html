1. Before the demo: checklist

Do these on the demo machine ahead of time, not in front of the audience. Every step here is one-off or quick.

StepWhy
☐Get the code and the model. Install Git LFS once (git lfs install). The repository also holds the Gemma 4 E2B, so fetch only the demo model: clone with git clone -c "lfs.fetchinclude=models/gemma-4-e4b-it-qat/*" <repository URL>, or in an existing clone run git config lfs.fetchinclude "models/gemma-4-e4b-it-qat/*" before git pull. Check that models/gemma-4-e4b-it-qat/ holds four files ending -00001-of-00004.gguf … -00004-of-00004.gguf, about 4 GB together (30 MB, 1.5 GB, 1.4 GB, 1.0 GB), not small text placeholders. Every download counts against GitHub's 10 GiB of LFS bandwidth a month: 3.9 GiB for the demo model, 6.8 GiB for both.

Ready when

The sidebar card shows READY with 32K context, the Code tab shows your demo project, and a warm-up chat answered at 100+ tokens per second.
I added the demo project through the app's API during the rehearsal, so "Open or create a project…" is the one screen I did not click through myself. After it, the new-task screen should show the project name, its path, and three quick actions (Understand this project, Plan a change, Find a bug).

2. A plain chat

In the Chat tab, start a new chat and send:

Give me three short tips for writing clear commit messages.

What should happen

The answer streams in straight away as a numbered list. Under it: the model name, First text, Output speed and Total.

I saw: first text 0.5 s, 100 tokens per second, done in 1.6 s. In the test suite, nine different chat questions took 0.3–2.3 s each at 113–129 tokens per second (higher is faster).

3. Ask about the code (Ask mode)

In the Code tab, press New task, pick Ask below the message box, and send:

What does this project do, and how is the tax applied to an order?

What should happen

The agent lists the folders, reads project/README.md and project/orders.py, then answers. Nothing is changed and nothing asks for approval (Ask mode reads freely).

I saw: five steps, no retries, correct answer: a command-line tool that reads an order from JSON and prints the total; TAX_RATE = 0.08; order_total multiplies the subtotal by 1 + tax_rate and rounds to two decimals.

4. Plan a change, keep planning, then approve

Start a new task, pick Plan, and send:

Add a function total_quantity(items) to project/orders.py that returns the sum of all item quantities, with a unit test in project/test_orders.py.

What should happen

The agent reads both files and presents a plan. A card appears: The plan is ready — Yes, accept edits · Yes, ask before edits · No, keep planning. Nothing has been changed yet.
  1. Press No, keep planning. The card closes, the mode stays on Plan, and the cursor is back in the message box.
  2. Send the refinement:
    Also run the tests with python -m unittest inside the project folder after the change.
    A new plan arrives that includes running the tests, with the card again.
  3. Press Yes, accept edits. The mode switches to Accept edits and the agent starts working without asking for file edits.
  4. When it wants to run the tests it stops with Waiting for approval. Press Review the request: the card names the command, python -m unittest (in project). Press Allow once.

What should happen

orders.py gains total_quantity, test_orders.py gains a test, and the tests pass. Each file change has View changes, showing only the changed lines.

I saw: the model first forgot to import the new function, so the test run failed with a NameError. It read the error, fixed the import and asked to run the tests again (a second Allow once). All three tests then passed.

Commands ask every time in Ask and Accept edits, so there is no "Allow for session" for them. To let a whole task run without prompts, use Auto (next flow).

5. Build an app from scratch (Auto mode)

Start a new task, pick Auto, and send:

Create a to-do list web app in a new folder named todo: a single index.html with its CSS and JavaScript inside. I can add a task, tick it as done, and delete it.

What should happen

No approval prompts. The agent creates todo/index.html, checks it, and reports. Open that file in your browser: type a task and press Add Task; click a task to mark it done; Delete removes it; the list survives a reload.

I saw: about 50 s. Everything worked; empty tasks are ignored. On an earlier try, before a fix made that morning, the model wrote the page into the wrong folder. The app now catches that and sends it back.

6. The two test-suite apps

The same way (new task, Auto), these are the exact prompts the automated test runs used:

Create a basic calculator web app in a new folder named calculator: a single index.html with its CSS and JavaScript inside. It needs buttons for the digits 0-9, +, -, ×, ÷, a decimal point, clear and equals, and a display that shows what is typed and the result.
Create a web app in a new folder named clock: a single index.html with its CSS and JavaScript inside, with three tabs: a live digital clock, a stopwatch with start, stop and reset, and a countdown timer where the user enters minutes and seconds and presses start.

What I saw

Calculator in 47.8 s: I clicked 7+5=12, 6×7=42, 9÷4=2.25, 3−8=−5, 1.5+2.25=3.75 and 2+3×4=14 (correct order of operations); C resets. The model's own slips: a second "=" button, and "/" on the divide key.
Clock in 54.3 s: styled page, ticking clock, Stopwatch and Countdown tabs.

7. Switching modes

  • Click Ask, Accept edits, Plan or Auto under the message box, or press Shift+Tab in the message box to cycle Ask → Accept edits → Plan. Auto is left out of the cycle on purpose; pick it with a click.
  • Ask: reads freely; edits, commands and deletions ask. Accept edits: reads and file edits run; commands, deletions, Git and web search ask. Plan: read-only, ends with a plan to approve. Auto: carries out the task without prompts.

9. Rough edges to know about

  • A 4B model still makes small mistakes. Examples from today: "/" instead of "÷", a forgotten import (it fixed that itself after the test failed), and a docstring edit that removed the def line it was documenting. Asking it to run the tests after a change, and looking at View changes, shows these quickly.
  • Technical wording in the activity list. When a reply cannot be read, progress rows mention things like "the constrained JSON format". The run carries on; the wording is not yet plain.
  • New code sessions stay titled "New task" in the sidebar.
  • The "Last used with another model" banner in an old chat stays after the next reply.
  • Start each demo in a fresh task. A long session carries earlier tasks in its history, which a small model can confuse with the new request.

10. Afterwards

Delete the demo-run folder (or send it to the Recycle Bin). The app keeps the sessions in its history until you delete them from the sidebar.
